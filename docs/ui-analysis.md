# 亲情陪伴系统前端 UI 与路由分析文档

## 0. 范围说明

本次分析覆盖当前仓库中的 Next.js 产品化前端：`web/src/app`。

未统计 `docs/*.html` 项目文档静态页。

---

## 1. 页面清单

| 页面名称 | 路由地址 | 页面用途 | 当前功能状态 |
|---|---|---|---|
| 首页 | `/` | 产品入口与功能导航 | 可用，偏测试版导航页 |
| 手机号登录 | `/login` | 用户登录、验证码登录 | 可用，测试期默认验证码 `000000` |
| 老人端语音陪伴 | `/elder` | 给老人使用的电话式语音聊天界面 | 可用，依赖登录、家庭空间、麦克风、后端 ASR/TTS |
| 家庭空间 | `/family` | 创建/查看家庭空间，进入家属管理流程 | 可用，单家庭空间模型 |
| 档案与记忆 | `/records` | 导入、解析、编辑、保存老人画像、AI 角色、家人档案、记忆 | 可用，功能较密集 |
| 对话历史 | `/history` | 查看老人端对话、筛选、重播、保存为长期记忆 | 可用，管理效率尚可但信息密度高 |
| 音色管理 | `/voices` | 管理豆包音色、导入已有音色、创建复刻音色、绑定 AI 角色 | 可用，偏后台工具形态 |

# 3. 功能模块分析

## 老人端聊天

面向老人，核心是低学习成本的语音通话式交互。老人只需要点击大按钮说话，系统完成录音、识别、回复生成、语音播放和最近对话展示。

## 用户登录

当前使用手机号验证码登录。测试期可用任意手机号和 `000000` 验证码。登录状态保存在浏览器本地，用于访问家庭空间、老人端、档案、历史、音色等页面。

## 家庭空间

家庭空间是云端数据归属单位。老人画像、家人档案、AI 角色、家庭记忆、音色、对话历史都挂在同一个家庭空间下。当前模型偏单家庭空间，适合 MVP。

## 老人画像

记录老人的姓名、性别、性格、偏好、习惯、健康备注、说话特点、人生经历、重要记忆等，供 AI 回复时调整语气和内容。

## AI 角色 / 人物画像

记录 AI 要扮演的家人身份，例如女儿、儿子、孙辈等，包括对老人的称呼、关系、性格、说话风格和陪伴方式。老人端会根据对话匹配或延续当前角色。

## 家人档案

记录真实家人的基本信息、性格、偏好、习惯、家庭关系和备注。用于让 AI 在聊天时更自然地提到家庭成员。

## 家庭记忆 / 记忆库

保存可用于陪伴对话的家庭事件、习惯、偏好、重要日期、趣事等。当前支持手动新增、智能解析导入、从对话历史保存为记忆。

## 对话历史

记录老人端语音对话的文本、AI 回复、音频、角色、老人、音色和 ASR/TTS 信息。家属可复盘对话，并把有价值内容沉淀为长期记忆。

## 音色管理

管理豆包语音音色，包括预置音色、已有 Speaker ID、复刻音色。音色可绑定到 AI 角色，使老人听到更像家人的声音。

## 云端同步

Next.js 前端通过后端 API 读写家庭空间、档案、记忆、历史、音色等云端数据。

# 4. 用户流程分析

## 4.1 老人用户流程

1. 进入系统  
   老人通常由家属提前登录并打开 `/elder` 页面。

2. 查看当前对话对象  
   页面显示“正在和 家人 说话”，老人知道当前是在和家人声音聊天。

3. 开始说话  
   老人点击大圆形“开始说话”按钮。

4. 结束并发送  
   说完后点击“结束并发送”，系统进入理解和回复状态。

5. 听到 AI 回复  
   系统播放合成语音，页面显示最近对话文本。

6. 继续聊天或重播  
   老人可继续点击开始说话，也可点击“重播上一条”。

7. 异常情况  
   如果家庭资料未准备好，页面提示“请家人先完成设置”；如果麦克风权限失败，页面提示无法录音。

## 4.2 家属用户流程

1. 进入系统  
   家属从首页进入登录页，使用手机号验证码登录。

2. 创建家庭空间  
   登录后进入 `/family`，创建默认家庭空间。

3. 完善档案与记忆  
   进入 `/records`，粘贴家庭资料，选择家人视角或老人视角，点击智能解析。

4. 审核并保存资料  
   在解析预览中检查老人画像、AI 角色、家人档案和家庭记忆，必要时手动修改，然后保存到云端。

5. 配置音色  
   进入 `/voices`，导入已有音色或创建复刻音色，并绑定到 AI 角色。

6. 交给老人使用  
   打开 `/elder`，确认可以录音和播放后交给老人。

7. 复盘对话  
   进入 `/history` 查看对话，筛选角色、老人和时间，重播音频。

8. 沉淀长期记忆  
   对重要对话点击“生成记忆候选”或“保存为记忆”，编辑后确认保存，后续聊天可使用这些记忆。

# 5. UI 问题分析

## 信息层级

当前界面更像测试后台，功能都能找到，但主次关系不够清晰。老人端已经有明确主按钮，但家属端多个页面同时承载导入、编辑、删除、保存、刷新等操作，视觉优先级接近，用户需要自己判断下一步。

## 操作步骤

家属初始化流程依赖多个页面串联：登录、家庭空间、档案、音色、老人端。页面间有入口，但缺少统一的新手引导、完成度提示和“下一步必须做什么”的明确路径。

## 页面布局

整体采用简单卡片和表单堆叠。`/records` 和 `/voices` 信息密度较高，表单字段多，长页面中用户容易迷失。`/voices` 左侧导航是后台形态，移动端和非技术家属使用时可能不够直观。

## 组件组织

大量操作按钮使用相似样式，危险操作、主操作、次操作、状态操作的区分不够强。比如保存、刷新、删除、展开编辑都在同一区域出现，缺少分组和确认层级。

## 老人易用性

老人端方向正确：大按钮、少文本、电话式交互。但仍存在问题：

- 最近对话文本对部分老人可能仍然过多。
- 错误状态偏技术化，例如麦克风权限、浏览器不支持。
- 没有明显的“呼叫中 / 家人在说话 / 我可以说了”的强视觉状态。
- 没有面向老人视力和手部操作的超大字号模式。

## 家属管理效率

家属端功能完整，但管理效率一般：

- 档案和记忆缺少概览仪表盘。
- 不容易看出哪些资料已经完整、哪些仍缺失。
- 记忆库缺少搜索、标签筛选、批量整理。
- AI 角色和音色绑定关系分散在不同页面。
- 对话历史到长期记忆的流程已经存在，但仍偏表单化，缺少“推荐保存原因”和快速确认体验。
