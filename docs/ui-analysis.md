# 亲情陪伴系统前端 UI 与路由分析文档

## 0. 范围说明

本次分析覆盖当前仓库中的 Next.js 产品化前端：`web/src/app`，以及对应的后端 API 客户端 `web/src/lib/`。

技术栈：Next.js 16 (App Router) + React 18 + TypeScript，全局 CSS 样式，无 UI 组件库。

未统计 `docs/*.html` 项目文档静态页。

---

## 1. 页面清单

| 序号 | 页面名称 | 路由地址 | 页面用途 | 当前功能状态 |
|------|----------|----------|----------|-------------|
| 1 | 首页 | `/` | 产品入口与功能导航 | 可用，偏测试版导航页 |
| 2 | 手机号登录 | `/login` | 家属用户登录，手机号+验证码 | 可用，测试期内测验证码 `000000` |
| 3 | 老人端语音陪伴 | `/elder` | 老人使用的电话式语音聊天界面 | 可用，依赖登录、家庭空间、麦克风权限、后端 ASR/TTS |
| 4 | 家庭空间 | `/family` | 创建/查看家庭空间，查看资料完成度，进入后续配置 | 可用，单家庭空间模型 |
| 5 | 档案与记忆 | `/records` | 导入解析+编辑保存老人画像、AI角色、家人档案、家庭记忆 | 可用，功能密集，字段数量大 |
| 6 | 对话历史 | `/history` | 查看老人端对话记录，筛选，重播，保存为长期记忆 | 可用，信息密度高 |
| 7 | 音色管理 | `/voices` | 管理豆包音色库，导入已有音色，创建复刻音色，绑定AI角色 | 可用，偏后台工具形态，含试听和状态查询 |

### 全局导航

顶部导航栏（NavBar）在所有页面显示（`/login` 除外），包含 6 个导航项：

- 首页 `/`
- 老人陪伴 `/elder`
- 家庭空间 `/family`
- 档案记忆 `/records`
- 音色 `/voices`
- 历史 `/history`

当前路由高亮激活，底部有 2px 棕色下划线指示。

## 2. 页面结构分析

### 2.1 首页 `/`

**页面区域：**
- 顶部登录状态栏（右侧对齐）
- 产品标题区（居中）
- 简短说明文案
- 主操作按钮区（两个大按钮）
- 功能卡片网格区（5 张卡片，响应式布局）

**组件：**
- 登录状态文本："已登录：{手机号}"
- 主标题："亲情陪伴系统"
- 说明文案："登录后默认进入老人端语音陪伴；家属管理入口用于维护档案、音色、记忆和历史。"
- 功能卡片（`<a>` 整卡可点击）：
  - 老人端语音陪伴 — "登录后优先进入电话式语音陪伴，让老人直接和家人声音聊天。"
  - 家属管理 — "创建家庭空间，作为档案、音色、记忆和对话历史的数据归属后台。"
  - 档案与记忆 — "集中管理老人信息、AI 扮演角色、家人档案和可用于对话的温暖记忆。"
  - 对话历史 — "查看老人端和家人声音 AI 的最近对话，按角色、老人和时间筛选，并重播已保存的 AI 回复。"
  - 声音克隆 — "导入或创建授权音色，并绑定到 AI 角色，用于老人端语音陪伴。"

**按钮：**
- "去登录"（未登录时）
- "开始语音陪伴"（主按钮，深色填充）
- "进入家属管理"（次要按钮，透明边框）
- "退出登录"（已登录时）
- 5 个功能卡片（整卡可点击跳转）

**表单：** 无

**数据展示：**
- 已登录用户手机号
- 5 个功能入口的名称和说明

**当前交互流程：**
1. 用户访问首页
2. 若未登录 → 看到"去登录"按钮 → 点击进入 `/login`
3. 若已登录 → 看到手机号和"退出登录"按钮 → 可直接进入老人端或家属管理
4. 点击任意功能卡片 → 跳转到对应页面

### 2.2 手机号登录 `/login`

**页面区域：**
- 登录面板（卡片式，最大宽度 520px）
- 表单区（手机号 + 验证码 + 两个按钮）
- 成功/错误提示区

**组件：**
- 标题："手机号登录"
- 提示文案："请输入内测账号和验证码登录。"
- 手机号输入框（类型 tel，placeholder："请输入内测账号"）
- 验证码输入框（placeholder："请输入测试版验证码"）

**按钮：**
- "检查账号"（发送验证码，发送中显示"检查中"）
- "登录"（提交登录，登录中显示"登录中"）

**表单字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 内测账号 | text (tel) | 手机号 |
| 验证码 | text (numeric) | 测试版验证码 |

**数据展示：**
- 成功提示："账号可用，请输入内测验证码登录。"（测试模式）
- 成功提示："验证码已发送。"（正式模式）
- 错误提示：具体的错误信息
- 按钮 disabled 状态：发送中、登录中、未填手机号、未填验证码

**当前交互流程：**
1. 用户输入手机号
2. 点击"检查账号" → 后台检查账号是否存在
3. 测试模式下页面提示验证码为固定值（`000000`）
4. 用户输入验证码 → 点击"登录"
5. 登录成功 → 自动跳转到 `/family`
6. 登录失败 → 页面显示错误信息

**重要状态：**
- 已登录用户自动跳转到 `/family`
- 未填手机号时"检查账号"按钮 disabled
- 手机号和验证码都未填时"登录"按钮 disabled
- 发送中和登录中按钮显示相应文字且 disabled

### 2.3 老人端语音陪伴 `/elder`

**页面区域：**
- 对话对象信息区（居中，顶部）
- 大型圆形通话按钮（居中，最大 260px）
- 辅助操作按钮区（居中，按钮行）
- 连续对话开关和提示区
- 错误/状态提示区
- 设置提示区（资料未准备好时显示）
- 最近对话区（左侧对齐，最多 3 轮）

**组件：**
- 称呼标签："正在和"
- 当前 AI 角色名（大标题，如"女儿 说话"）
- 音色绑定提示（已绑定："已使用绑定音色：妈妈的声音"；未绑定："还没有给这个家人绑定音色"）
- 通话状态文本：
  - 空闲："可以开始说话啦"
  - 录音中："正在听你说"
  - 录音完成："说完啦，可以发送"
  - 理解中："正在理解你说的话"
  - 回复生成中："正在回复"
  - 播放中："正在播放回复"
  - 出错："刚才有点卡住了"
- 大圆形通话按钮（直径 max 260px，带状态颜色变化）
- 连续对话开关按钮
- 最近对话卡片（每张含：您说 / AI角色说 / 重播按钮）

**按钮：**

| 按钮 | 出现时机 | 作用 |
|------|----------|------|
| 开始说话 | idle 状态 | 开始录音 |
| 结束并发送 | recording 状态 | 停止录音并发送 |
| 发送 | recorded 状态 | 发送已完成的录音 |
| 打断说话 | playing 状态 | 停止播放 |
| 取消本轮 | recording 状态 | 取消当前录音 |
| 重新说 | recorded 状态 | 重新开始录音 |
| 停止播放 | playing 状态 | 停止播放音频 |
| 重播上一条 | idle 且有音频记录 | 重播最新一条 AI 语音回复 |
| 连续对话：开/关 | setup ready | 切换连续对话模式 |
| 重播 | 每条有音频的对话 | 重播该条 AI 回复 |
| 家属去设置 | setup missing | 跳转到 `/family` |

**表单：** 无传统表单；核心输入方式为浏览器麦克风录音。

**数据展示：**
- 当前 AI 角色名称
- 音色绑定状态
- 最近 3 轮对话（文字 + 可选音频重播）
- 空状态："还没有最近对话。"

**当前交互流程（完整状态机）：**

```
idle（可以开始说话啦）
  ↓ 点击"开始说话" → 请求麦克风权限
recording（正在听你说）
  ↓ 点击"结束并发送" → 停止录音 → 显示"说完啦"
recorded（说完啦，可以发送）
  ↓ 点击"发送" → 上传音频到后端
understanding（正在理解你说的话）
  ↓ 自动 → ASR 识别
replying（正在回复）
  ↓ 自动 → LLM 生成回复 + TTS 合成
playing（正在播放回复）
  ↓ 播放结束 → idle（普通模式）或 recording（连续对话模式）
```

错误处理：
- 麦克风权限拒绝 → 显示错误提示
- 浏览器不支持录音 → 显示错误提示
- 语音识别为空 → 提示"刚才没有听清"
- 后端失败 → 显示错误提示
- 家庭资料未准备好 → 显示"陪伴资料还没准备好"，引导家属设置

**音色匹配逻辑：**
- 初始加载时，自动匹配第一个 AI 角色的绑定音色
- 对话过程中，后端可能返回匹配的新角色（通过 `matched_persona`）
- 若匹配的角色不同，前端自动切换当前角色名称和音色

### 2.4 家庭空间 `/family`

**页面区域：**
- 页面标题说明区
- 加载/错误/成功提示区
- 已创建家庭空间状态区（家庭信息 + 资料完成度 + 下一步入口）
- 未创建家庭空间表单区

**组件：**

已创建家庭空间时：
- 家庭名称（大标题）
- 家庭 ID（辅助文本）
- 成员角色标签（所有者 / 可编辑成员 / 只读成员 / 未加入）
- 用户 ID 标签
- **陪伴资料完成度**（4 项检查清单）：
  - ✅/⬜ 老人画像
  - ✅/⬜ AI 角色
  - ✅/⬜ 家庭记忆
  - ✅/⬜ 音色
- 完成度提示文本：
  - 全部完成："所有资料已就绪，老人可以开始语音聊天了。"
  - 未完成："请继续完善上方缺失的资料，完成后老人端即可开始语音陪伴。"
- "下一步"卡片网格（4 个入口）：
  - 完善档案与记忆 → `/records`
  - 管理家人音色 → `/voices`
  - 查看对话历史 → `/history`
  - 进入老人端 → `/elder`

未创建家庭空间时：
- 提示："尚未创建家庭空间"
- 说明："首版默认使用单家庭空间；创建者会成为 owner，后续邀请家人默认成为 editor。"
- 家庭空间名称输入框

**按钮：**
- "创建家庭空间"（未创建时，创建中显示"创建中..."）
- "完善档案与记忆"（已创建时，跳转到 `/records`）
- "刷新"（重新加载家庭空间数据）
- "返回首页"（跳转到 `/`）
- 4 个下一步入口卡片

**表单字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| 家庭空间名称 | text | 创建时必填 |

**数据展示：**
- 家庭名称
- 家庭 ID（完整显示）
- 当前用户成员角色（中文标签）
- 当前用户 ID
- 陪伴资料完成度（4 项的勾选状态）
- 加载中："正在加载家庭空间..."
- 未创建时："尚未创建家庭空间"

**当前交互流程：**
1. 登录后进入 `/family`，系统自动加载用户所属的家庭空间
2. 若无家庭空间 → 输入名称 → 点击"创建家庭空间" → 创建成功，显示家庭信息和下一步入口
3. 若有家庭空间 → 显示家庭信息 → 查看资料完成度 → 点击下一步入口进入配置流程
4. 点击"刷新"重新检查资料完成度

### 2.5 档案与记忆 `/records`

这是整个家属端功能最密集的页面，分为上下两大区域。

**页面区域：**
- 页面标题说明区（含当前家庭名称）
- **上半部分：智能导入区**
  - 描述视角切换（家人视角 / 老人视角）
  - 大文本框（自由文本输入）
  - 操作按钮行
  - 解析结果预览区（4 类可编辑数据）
- **下半部分：已保存云端档案管理区**
  - 操作按钮行
  - 已保存记录列表（4 类，可展开编辑/删除）

**组件：**

智能导入区：
- 视角分段控件（segment control）：家人视角 / 老人视角（二选一高亮）
- 大文本输入框（id="sourceText"，placeholder 示例："老人叫宋桂兰，女儿小雨每周都会打电话。去年中秋，小雨陪妈妈在院子里赏月。"）
- "同步创建为家人档案"复选框

解析预览区（4 类可编辑卡片）：
- 老人画像（单条，字段表单）
- AI 扮演角色（单条 + 多条列表，字段表单）
- 家人档案（列表，每条含字段表单）
- 家庭记忆（列表，每条含字段表单）

已保存云端档案管理区（4 类）：
- 老人画像（列表，可展开编辑 / 删除）
- AI 扮演角色（列表，可展开编辑 / 删除）
- 家人档案（列表，可展开编辑 / 删除）
- 家庭记忆（列表，可展开编辑 / 删除）

**按钮：**

| 按钮 | 区域 | 作用 |

| 保存修改 | 管理区 | 将已保存记录的编辑内容提交到后端 |
| 刷新 | 管理区 | 重新加载云端数据 |
| 展开编辑 | 管理区每条记录 | 展开该条记录的编辑表单 |
| 收起 | 管理区每条记录 | 收起编辑表单 |
| 删除 | 管理区每条记录 | 删除该条云端记录（无确认弹窗） |

**表单字段：**

老人画像（10 个字段）：

|------|------|

| 性别 | |
| 性格 | 数组字段，顿号分隔 |

| 重要记忆 | 数组字段，顿号分隔 |
| 备注 | |

AI 扮演角色（6 个字段）：

| 字段 | 说明 |
|------|------|
| 角色名 | |
| 与老人关系 | |
| 对老人称呼 | |
| 性格 | 数组字段 |
| 说话风格 | 数组字段 |
| 陪伴方式 | 数组字段 |

家人档案（8 个字段）：

| 字段 | 说明 |
|------|------|
| 姓名 | |
| 性别 | |
| 关系 | |
| 性格 | 数组字段 |
| 偏好 | 数组字段 |
| 习惯 | 数组字段 |
| 家庭关系 | 数组字段 |

家庭记忆（7 个字段）：

| 字段 | 说明 |
|------|------|
| 记忆内容 | 核心字段 |
| 类型 | 如"对话"、"事件" |
| 主语 | 如老人姓名 |
| 相关家人 | 数组字段，逗号分隔 |
| 情感标签 | 数组字段，逗号分隔 |

总计最多 31 个不同字段，其中 12 个为数组类型需特殊处理。

**数据展示：**
- 当前家庭名称
- 解析后预览数据（空状态："解析后会在这里显示可编辑预览。"）
- 已保存云端数据（空状态："暂无已保存的云端档案或记忆。"）
- 保存成功提示（含各项保存数量统计）
- 删除成功提示

**当前交互流程：**

导入流程：
1. 家属粘贴家庭资料到文本框
2. 选择描述视角（家人视角 / 老人视角）
3. 点击"智能解析" → LLM 解析文本
4. 检查预览区 4 类数据的解析结果
5. 手动编辑不满意或缺失的字段
6. 勾选"同步创建为家人档案"（将 AI 角色信息同步到家人档案）
7. 点击"保存到云端" → 数据写入后端

管理流程：
1. 页面加载时自动拉取当前家庭空间的云端数据
2. 在"已保存的云端档案与记忆"区域查看 4 类数据
3. 点击"展开编辑" → 编辑字段 → 点击"保存修改"提交
4. 点击"删除"直接删除云端记录

### 2.6 对话历史 `/history`

**页面区域：**
- 页面标题区（含家庭名称和说明）
- 筛选工具栏（3 个下拉 + 刷新按钮）
- 状态提示区
- 对话轮次列表（每轮一条卡片）
- 记忆保存编辑面板（内嵌在卡片中）

**组件：**
- 筛选器（3 个下拉框 + 1 个按钮）：
  - AI 角色下拉（动态生成，来自历史数据中的角色）
  - 老人下拉（动态生成，来自历史数据中的老人）
  - 时间下拉（固定选项：全部时间 / 今天 / 最近 7 天 / 最近 30 天）
- 对话卡片：
  - 元信息行：时间、角色名、老人名、音色名
  - 对话内容：老人说（原文）+ AI 回复
  - 底部信息行：ASR 提供方、TTS 提供方、重播按钮
  - 操作按钮：生成记忆候选 / 保存为记忆 / 已保存为记忆（徽标）

## 3. 功能模块分析

### 3.1 用户认证
- 手机号 + 验证码登录
- 测试期支持固定验证码 `000000`
- Token 存储在浏览器 localStorage
- 登录过期后自动跳转登录页

### 3.2 家庭空间
- 云端数据归属单位，所有档案、记忆、音色、对话历史都挂在家庭空间下
- 当前为单家庭空间模型（每个用户一个家庭空间）
- 三种成员角色：owner（所有者）、editor（可编辑）、viewer（只读）
- 提供资料完成度检查（老人画像/AI角色/家庭记忆/音色四项）

### 3.3 老人端语音聊天
- 面向老人的电话式语音交互界面
- 大圆形按钮为核心操作元素
- 完整状态机：idle → recording → recorded → understanding → replying → playing
- 支持连续对话模式
- 自动匹配和切换 AI 角色与绑定音色
- 最近 3 轮对话展示 + 历史重播

### 3.4 老人画像管理
- 记录老人的 10 项属性（姓名、性别、性格、偏好、习惯、健康备注、说话特点、人生经历、重要记忆、备注）
- 支持 LLM 智能解析导入和手动编辑

### 3.5 AI 角色 / 人物画像
- 定义 AI 扮演的家人身份（6 项属性）
- 支持多个角色，老人端自动匹配最合适的角色
- 角色可绑定到具体音色

### 3.6 家人档案
- 记录真实家人信息（8 项属性）
- 供 AI 在对话中自然地提及家庭成员
- 支持从 AI 角色同步创建

### 3.7 家庭记忆库
- 存储可用于陪伴对话的家庭事件、习惯、偏好、重要日期等
- 输入来源：手动新增、LLM 智能解析导入、对话历史提取
- 7 项属性含亲密权重，用于排序和筛选

### 3.8 对话历史
- 记录每次语音对话的完整信息（文字、音频、角色、音色、ASR/TTS 提供方）
- 支持按角色、老人、时间三维筛选
- 支持从对话中提取和保存长期记忆（LLM 辅助 + 手动编辑）

### 3.9 音色管理
- 管理豆包语音音色，支持三种类型：预置、已导入、已复刻
- 导入已有 Speaker ID（无需重新训练）
- 创建复刻音色（上传音频样本 → 豆包训练）
- 音色绑定到 AI 角色
- 试听、状态查询、重命名、删除

### 3.10 云端同步
- Next.js 前端通过 REST API 与后端通信
- Token 认证（请求头 X-User-Token）
- 所有数据操作（CRUD）均通过 API，无本地持久化

## 4. 用户流程分析

### 4.1 老人用户流程

> 前提：家属已完成所有配置（家庭空间、老人画像、AI角色、家庭记忆、音色绑定）。

```
步骤 1：进入系统
  └→ 家属将 `/elder` 页面在老人设备上打开（已登录状态）

步骤 2：查看对话对象
  └→ 页面显示"正在和 [家人名字] 说话"，老人知道在和谁聊天

  └→ 点击大圆形"开始说话"按钮
  └→ 页面显示"正在听你说"，按钮变红

步骤 4：结束说话
  └→ 说完后点击"结束并发送"
  └→ 页面依次显示"正在理解"→"正在回复"
  └→ 按钮变灰

步骤 5：听到回复
  └→ 系统自动播放 AI 回复语音
  └→ 页面显示"正在播放回复"，按钮变绿
  └→ 最近对话区显示文字记录

步骤 6：继续聊天
  └→ 播放完毕后：

  └→ 可点击"重播上一条"再次听刚才的回复

步骤 7：异常处理
  └→ 如果说得太小声 → 提示"刚才没有听清"
  └→ 如果系统出错 → 提示"刚才有点卡住了"
  └→ 如果资料未就绪 → 提示"请家人先完成设置"
```

- 单个大按钮操作，无需阅读文字即可使用
- 状态通过按钮颜色+简短文字传达
- 无需键盘输入，全程语音
- 对老人视力和操作精度要求低

## 5. UI 问题分析

### 5.1 信息层级

**问题：**
- 首页功能卡片平等排列，没有突出"老人端"作为核心产品和"家属管理"作为配置工具的区别
- `/records` 页面同时承担"智能导入"和"已保存数据管理"两个大功能，视觉上同等重要，用户进入后不知道先看哪个
- `/family` 页面的资料完成度检查虽然存在，但视觉优先级不够高，容易被忽视
- 全局导航将"老人陪伴"和"家庭空间"并列，没有区分使用场景和频率

### 5.2 操作步骤

**问题：**
- 家属初始化流程跨 4+ 个页面（登录 → 家庭空间 → 档案 → 音色 → 老人端），缺少统一的新手引导向导
- 每个页面独立，没有"下一步"的明确指示和进度感
- 完成度检查在 `/family` 页，但具体操作要到其他页面完成，来回跳转
- 没有"快速配置"或"一键导入"的简化路径

### 5.3 页面布局

**问题：**
- `/records` 页面内容极长（导入区 + 预览区 + 管理区），用户需要大量滚动
- 预览区和管理区数据格式相同但位置分离，容易混淆
- `/voices` 左侧导航在后端管理系统中常见，但对非技术家属可能不够直观，移动端左侧导航更不友好
- `/history` 对话卡片信息密度高，每条卡片展示 10+ 条信息，缺少折叠和摘要视图
- `/elder` 老人端页面虽然简洁，但最近对话区在手机屏上可能被主按钮挤压

### 5.4 组件组织

**问题：**
- 大量按钮使用相似的 `.button` 和 `.buttonSecondary` 样式，主次操作、危险操作的视觉区分不够强
- 删除操作在 `/records` 管理区没有二次确认（除了音色页面有 confirm 弹窗）
- 保存、刷新、删除、展开编辑在同一个区域，缺少分组
- 音色卡片的编辑名称交互（✎ 图标 + 内联编辑）与整体卡片风格不太协调
- 表单字段没有必填/选填的视觉区分

### 5.5 老人易用性

**优点：**
- 大圆形按钮是正确方向
- 电话式交互符合老人认知模型
- 状态文字简短

**问题：**
- 最近对话文字对部分老人可能仍过多（3 轮对话文字 + 重播按钮）
- 错误提示偏技术化："当前浏览器暂时不能录音，请换一个浏览器再试"、"没有打开麦克风权限"
- 缺少明显的"呼叫中""家人在说话""我可以说了"的强视觉状态区分（目前只靠按钮颜色和文字）
- 没有面向老人的大字号模式（所有文字统一大小）
- 辅助按钮（连续对话、取消本轮、重新说）对老人来说可能是干扰
- 没有"只有我可以说话的时候"和"家人在回复我的时候"的明确视觉分区

### 5.6 家属管理效率

**问题：**
- 档案和记忆缺少概览仪表盘（一共多少条、最近更新时间、哪些待完善）
- 记忆库缺少搜索、标签筛选、批量操作（只能逐条展开编辑）
- AI 角色和音色绑定关系分散在 `/records` 和 `/voices` 两个页面
- 从对话历史到长期记忆的流程已存在，但每次只能处理一条，缺少批量保存
- 资料完成度检查只在 `/family` 页显示，进入配置页后不再可见
- 没有数据导出/备份功能

### 老人端语音陪伴

页面名称：老人端语音陪伴

- 通话状态文字，字号约 20px（如"可以开始说话啦"）
- 页面正中央：大圆形按钮（直径约 200-260px），深色填充，内含大字状态标签
- 按钮下方：辅助操作区，横向排列的小按钮（连续对话开关、重播上一条等）
- 底部：最近对话区，每轮对话显示在一个浅色卡片中：
  - "您说：……"（老人原话）
  - "女儿：……"（AI 回复）
  - 重播按钮（如有音频）

关键操作：
- 核心操作：点击大圆形按钮（在不同状态显示不同文字："开始说话""结束并发送""发送""打断说话"）

重要状态（大按钮颜色变化）：

- 录音中 = 红色按钮，文字"结束并发送"
- 录音完成 = 棕褐色按钮，文字"发送"

- 播放中 = 绿色按钮，文字"打断说话"
- 出错 = 显示错误提示文字

特殊状态：
- 资料未准备好：显示提示卡片"陪伴资料还没准备好"，含"家属去设置"按钮
- 麦克风权限失败：显示错误提示

设计要点：
- 所有元素大号、高对比度、适合老年人视力
- 主按钮足够大（手指可轻松点击）
- 状态变化通过颜色+文字双重传达
- 整体氛围温暖、安心

目标用户：老人用户（70岁以上，视力/操作能力可能下降）

  - 音色名称输入框

- 查询中/训练中：按钮显示对应文字并禁用
- 试听：自动播放音频，卡片下方出现播放器
- 创建成功：自动跳回音色库并显示成功提示

目标用户：家属用户，偏管理者或配置人员
